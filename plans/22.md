# Parameterise dev ports via direnv + Caddy env vars

## Reviewed files

- `Procfile`
- `Procfile.prod`
- `Caddyfile`
- `Caddyfile.prod`

## Current state

All three dev processes hardcode their ports:

| Process | Procfile command | Hardcoded port |
|---------|-----------------|----------------|
| **PocketBase** | `pocketbase serve --dev` | `:8090` (default) |
| **Astro** | `pnpm dev` | `:4321` (default) |
| **Caddy** | `caddy run` | `:8080` (in `Caddyfile`) |

- The reverse-proxy targets (`localhost:8090`, `localhost:4321`) are also hardcoded in `Caddyfile`.
- No `.envrc` or `.env` exists.
- Prod (`Caddyfile.prod` / `Procfile.prod`) serves on `:80` per the ONCE contract and is independent — it must not be affected by dev port changes.

## Goal

Introduce a **single source of truth for dev port assignments** so that:

1. All three processes pick up their ports from one place.
2. Ports are incremental from a configurable base (hivemind-style), keeping them predictable and free of collisions.
3. Changing the base port once renumbers all three.
4. Prod configs remain untouched.
5. The existing `Caddyfile` serves as the single reverse-proxy config (no duplication of port logic into the Procfile or shell scripts).

## Decisions

- Use **direnv (`.envrc`)** as the single source of truth — it exports into the shell automatically when you `cd` into the project directory, and hivemind inherits those exports.
- Use **bash parameter expansion** (`:=`) so the values have defaults but can be overridden via environment.
- Use **Caddy's `{env.VAR}` interpolation** so the Caddyfile reads the ports dynamically instead of duplicating them into the Procfile.
- Use the same default base port (5000) and step (100) that hivemind itself uses, so the behaviour matches what a developer would expect from `hivemind --port 5000`.
- `Procfile.prod` and `Caddyfile.prod` stay hardcoded — they are baked into the Docker image and run in a fixed ONCE-compatible environment.

## Proposed implementation

### 1. Create `.envrc`

```bash
: ${BASE_PORT:=5000}
: ${PORT_STEP:=100}

export PB_PORT=$BASE_PORT
export WEB_PORT=$((PB_PORT + PORT_STEP))
export CADDY_PORT=$((WEB_PORT + PORT_STEP))
export PORT=$BASE_PORT
```

After `direnv allow`, this exports:

| Variable | Default |
|----------|---------|
| `PB_PORT` | `5000` |
| `WEB_PORT` | `5100` |
| `CADDY_PORT` | `5200` |
| `PORT` | `5000` |

### 2. Update `Procfile` — reference env vars

```
pb: cd pocketbase && pocketbase serve --dev --http=0.0.0.0:${PB_PORT}
web: cd web && PORT=${WEB_PORT} pnpm dev
caddy: caddy run
```

PocketBase's `--http` flag [overrides the default `:8090`](https://pocketbase.io/docs/going-to-production/). Astro's dev server respects the `PORT` env var. Caddy reads its listen address from the Caddyfile below.

### 3. Update `Caddyfile` — use `{env.VAR}`

```
:{env.CADDY_PORT} {
	handle /_* {
		reverse_proxy localhost:{env.PB_PORT}
	}

	handle /api* {
		reverse_proxy localhost:{env.PB_PORT}
	}

	handle {
		reverse_proxy localhost:{env.WEB_PORT}
	}
}
```

[Caddy interpolates environment variables](https://caddyserver.com/docs/caddyfile/concepts#environment-variables) at config-load time using `{env.VAR}` syntax.

### 4. Generate a `.env.example` (optional, for contributors)

```bash
# .env.example — copy to .envrc and run `direnv allow`
# or just `direnv allow` and the defaults below take effect.
: ${BASE_PORT:=5000}
: ${PORT_STEP:=100}
```

### 5. Leave prod files unchanged

- `Procfile.prod` — no change (uses fixed paths and the `entrypoint.sh` wrapper).
- `Caddyfile.prod` — no change (listens on `:80`, proxies to `localhost:8090`).

## Data flow

```
  .envrc                         Procfile
  ──────                         ────────
  BASE_PORT=5000 ──► PB_PORT=5000 ──► pocketbase serve ... --http=0.0.0.0:5000
                  ──► WEB_PORT=5100 ──► PORT=5100 pnpm dev
                  ──► CADDY_PORT=5200
                  ──► PORT=5000

  Caddyfile
  ─────────
  :{env.CADDY_PORT} ────► :5200 (listen)
    localhost:{env.PB_PORT} ──► 5000 (proxy /_*, /api*)
    localhost:{env.WEB_PORT} ──► 5100 (proxy /*)
```

## Override examples

```sh
# Different base (useful if 5000 is taken)
BASE_PORT=7000 direnv allow   # PB=7000, Web=7100, Caddy=7200

# One-off without changing .envrc
BASE_PORT=8000 hivemind       # overrides at process level

# Bigger gaps between services
BASE_PORT=9000 PORT_STEP=200 hivemind   # PB=9000, Web=9200, Caddy=9400
```

## Acceptance criteria

1. `cd` into the project directory and `direnv allow` exports `PB_PORT`, `WEB_PORT`, `CADDY_PORT`, and `PORT` with the correct default values (5000, 5100, 5200, 5000).
2. `hivemind` launches all three processes on the expected ports.
3. Caddy reverse-proxies correctly: `http://localhost:5200/api/...` reaches PocketBase, `http://localhost:5200/` reaches Astro.
4. Changing `BASE_PORT` in `.envrc` renumbers all three ports and everything still works.
5. `Caddyfile.prod` and `Procfile.prod` are unchanged.
6. `.envrc` is added to `.gitignore` (it contains machine-local overrides; `.envrc` is typically **not** committed, but an `.envrc.example` or `.env.example` can be committed as documentation).
