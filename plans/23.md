# Plan 23 — Convert marketplace web theme to BigConfig light mode

## Goal

Change the current dark marketplace theme to a fixed light theme matching the visual language in `/home/ubuntu/code/workspace/once-bigconfig/main`, especially the light marketplace page style:

- light slate background (`#f8fafc`) and white/translucent surfaces
- slate text hierarchy instead of neutral-on-black
- yellow/amber marketplace accent everywhere, including applications
- sticky translucent white header, light dropdowns, light mobile drawer
- light cards, chips, inputs, code blocks, empty states, and dashboard-generated HTML

This is a fixed light theme conversion only. PocketBase schema, hooks, auth flow, data fetching, routes, and client-side behavior should remain unchanged.

## Decisions

- Palette: use the yellow/amber light palette from the reference `/marketplace` page.
- Item accents: use yellow/amber for both packages and applications; do not keep cyan/teal application accents.
- Theme mode: fixed light theme only; no toggle and no `prefers-color-scheme` implementation in this plan.
- Logo: keep the current marketplace `web/src/assets/logo.svg`.
- Documentation code blocks: convert to light code cards like the reference site.

## Proposed implementation

### 1. Add shared light-theme primitives

Update `web/src/styles/global.css` with reusable CSS variables/classes inspired by the reference site:

- `:root` light color tokens (`--bc-bg`, `--bc-surface`, `--bc-border`, `--bc-text`, `--bc-text-muted`, `--bc-text-subtle`, `--bc-accent`, `--bc-amber`, `--bc-yellow`)
- page shell: `.bc-page-light`, `.bc-page-glow`, `.bc-page-glow-yellow`
- header/nav: `.bc-site-header`, `.bc-nav-link`, `.bc-nav-link-yellow`
- surfaces/cards: `.bc-site-surface`, `.bc-site-card`, `.bc-site-card-yellow`, `.bc-code-card`
- chips/inputs/text helpers: `.bc-chip`, `.bc-input-light`, `.bc-muted`, `.bc-subtle`, `.bc-footer-link`

Keep Tailwind v4 import as `@import "tailwindcss"`; do not add a Tailwind config.

### 2. Convert shared shell and navigation

- `web/src/layouts/Layout.astro`
  - change body from `bg-neutral-950 text-neutral-100` to `bc-page-light`
  - replace dark yellow radial gradient with the reference light glow (`bc-page-glow bc-page-glow-yellow`)
- `web/src/components/Header.astro`
  - convert sticky header to translucent white/slate border
  - convert active/hover nav states to amber/yellow on slate text
  - convert desktop user dropdown and mobile menu to white surfaces with slate borders/text
  - keep all auth/menu JS unchanged except class names where necessary
- `web/src/components/Footer.astro`
  - convert to slate muted text and light footer link styling

### 3. Convert reusable cards and tags

- `web/src/components/PackageCard.astro`
  - use white card surfaces and slate text
  - keep yellow accent bar/badge for packages
- `web/src/components/ApplicationCard.astro`
  - use white card surfaces and slate text
  - convert application accent bar/badge to yellow/amber for consistency with packages
- `web/src/components/TagChip.astro`
  - convert default tags to light chips
  - keep highlighted tag state readable on yellow

### 4. Convert pages and client-rendered markup

Update all pages that currently hardcode dark classes:

- landing/listing pages: `index.astro`, `packages.astro`, `applications.astro`
- detail pages: `packages/[owner]/[repo].astro`, `applications/[owner]/[repo].astro`
- auth/submission/edit/dashboard pages: `login.astro`, `submit.astro`, `applications/submit.astro`, `me/*.astro`
- docs page: `documentation.astro`

Important: update both static Astro markup and any JavaScript-generated HTML strings in dashboard pages (`grid.innerHTML` records/status/chips/buttons), otherwise dashboards will retain dark cards inside a light page.

### 5. Preserve behavior while changing visuals

- Do not alter data loading, PocketBase calls, auth storage, protected-field behavior, route paths, or form submission payloads.
- Keep `data-*` attributes used by scripts (`data-menu-*`, `data-user-*`, filters, copy buttons, etc.).
- Preserve responsive layouts and mobile drawer behavior.
- Preserve `PUBLIC_PB_URL` behavior.
